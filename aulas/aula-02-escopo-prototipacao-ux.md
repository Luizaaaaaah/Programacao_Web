## 1. Tipos de aplicações web

As aplicações web podem ser classificadas conforme sua finalidade. A classificação pode variar de acordo com a referência bibliográfica utilizada.

Entre os principais tipos apresentados estão:

| Tipo | Descrição |
|---|---|
| Institucional | Apresenta informações sobre uma empresa ou organização. |
| Blog | Publica conteúdos, artigos e notícias. |
| E-commerce | Permite a comercialização de produtos ou serviços pela internet. |
| Landing Page | Página direcionada a uma ação específica, como cadastro ou divulgação. |
| Plataforma | Disponibiliza funcionalidades e serviços aos usuários. |

A definição do tipo de aplicação contribui para o planejamento de sua estrutura e funcionalidades.

## 2. Arquitetura de um site

A arquitetura de um site representa a organização de suas páginas, conteúdos e caminhos de navegação.

Durante a aula, foi apresentada a ferramenta **Octopus.do**, utilizada para criar representações visuais da estrutura de sites.

**Ferramenta:** https://octopus.do/

O planejamento da arquitetura facilita a visualização das páginas e de seus relacionamentos antes do desenvolvimento.

## 3. Escopo e backlog do projeto

O escopo define os objetivos, as funcionalidades e os limites de um projeto.

Sua elaboração é importante para organizar o desenvolvimento e alinhar as expectativas entre os envolvidos.

### Principais aspectos

- Definição dos objetivos do projeto;
- Identificação dos principais requisitos;
- Documentação das funcionalidades;
- Alinhamento com os stakeholders;
- Organização e gerenciamento do backlog.

O **backlog** reúne as tarefas, funcionalidades e requisitos que precisam ser desenvolvidos ao longo do projeto.

### Exemplo de escopo apresentado na aula

O slide utiliza como exemplo um site institucional para uma empresa fictícia chamada XYZ.

O objetivo é apresentar a identidade da empresa, seus produtos e serviços, além de facilitar o contato com clientes.

O projeto contempla:

- Página inicial;
- Seção sobre a empresa;
- Blog;
- Formulário de contato;
- Layout responsivo;
- Navegação intuitiva;
- Recursos de usabilidade e acessibilidade.

As tecnologias previstas no exemplo são HTML, CSS, JavaScript e um CMS para gerenciamento de conteúdo.

## 4. Planejamento e gestão do backlog

O planejamento do backlog permite organizar as atividades necessárias para o desenvolvimento da aplicação.

Entre os benefícios apresentados estão:

- Facilitar a comunicação entre a equipe e o cliente;
- Melhorar a experiência do usuário desde o início;
- Definir uma estrutura clara para o desenvolvimento;
- Organizar as necessidades utilizando User Stories.

A gestão das tarefas contribui para acompanhar as etapas do projeto e os itens que ainda precisam ser realizados.

## 5. User Stories

As **User Stories**, ou histórias de usuário, descrevem funcionalidades considerando as necessidades de quem utilizará o sistema.

O formato solicitado na atividade foi:

> Como (quem?), eu quero (o que?) para (por que?).

### Exemplo apresentado na aula

O material apresenta a necessidade de um visitante acessar a página "Sobre" para conhecer a história, os valores e a missão de uma empresa.

Essa funcionalidade permite obter informações sobre a organização e contribui para uma navegação mais clara e intuitiva.

As histórias de usuário ajudam a compreender as necessidades do público-alvo e a orientar o desenvolvimento das funcionalidades.

## 6. Gestão de tarefas com Kanban

O **Kanban** é uma forma visual de organizar e acompanhar as tarefas de um projeto.

O slide apresenta o quadro Kanban como uma ferramenta colaborativa, prática e também como um tipo de documentação do projeto.

Por meio de um quadro, a equipe consegue acompanhar o andamento das atividades.

**Complemento — Exemplo de organização de um quadro:**

- A fazer;
- Em andamento;
- Concluído.

Na atividade, o professor solicitou a utilização do **Trello** para criar o quadro Kanban e registrar as tarefas já realizadas.

## 7. Wireframes

Um **wireframe** é uma representação visual da estrutura de uma interface.

Ele permite planejar a distribuição dos elementos e a organização das telas antes da implementação.

### Tipos de wireframes

**Baixa fidelidade:** representação simples da interface, destacando principalmente sua organização e estrutura.

**Alta fidelidade:** representação mais detalhada, próxima da aparência planejada para a interface.

Os wireframes são utilizados para estruturar o site, analisar sua navegação e auxiliar na validação das ideias.

Durante a aula, foram apresentados exemplos práticos e ferramentas utilizadas na criação de wireframes, como o Figma.

**Ferramenta:** https://www.figma.com/

## 8. Ferramentas de prototipação

A prototipação permite representar e testar ideias antes de desenvolver a aplicação completa.

Entre os recursos abordados estão:

- Criação de protótipos a partir de imagens e prompts;
- Utilização de plugins do Figma;
- Validação de ideias;
- Realização de ajustes e iterações.

### Plugins apresentados

- **html.to.design:** ferramenta relacionada à importação de interfaces para o Figma.
- **Musho.ai:** ferramenta que utiliza inteligência artificial para auxiliar na criação de interfaces.

Também foi apresentada a exportação de arquivos no formato `h2d`.

## 9. Atividade proposta

A atividade da Aula 02 está relacionada ao planejamento e à prototipação do projeto definido pelo grupo.

### Etapa 1 — Pesquisa de aplicações semelhantes

Após definir o tema do projeto, pesquisar aplicações web semelhantes existentes no mercado.

Durante a pesquisa, identificar os pontos fortes e fracos das soluções analisadas.

### Etapa 2 — Análise da estrutura

Analisar a estrutura da aplicação web proposta, descrevendo:

- Principais componentes;
- Fluxo de navegação;
- Arquitetura do projeto.

### Etapa 3 — User Stories e wireframes

Elaborar **três User Stories**, seguindo o formato:

> Como (quem?), eu quero (o que?) para (por que?).

Em seguida, criar wireframes das primeiras telas do projeto, representando suas interfaces principais.

### Etapa 4 — Kanban no Trello

Criar uma conta no Trello e configurar um quadro Kanban para organizar as atividades do projeto.

O quadro deverá apresentar:

- Atividades que precisam ser realizadas;
- Organização visual das tarefas;
- Registro dos itens já concluídos.

A documentação da atividade deverá demonstrar as etapas efetivamente desenvolvidas pelo grupo.

## 10. Conclusão

A Aula 02 apresentou a importância do planejamento no desenvolvimento de aplicações web.

Foram estudados conceitos de escopo, backlog, arquitetura, histórias de usuário, Kanban e wireframes.

Esses conhecimentos auxiliam na organização dos projetos, na definição das funcionalidades e na criação de interfaces que atendam às necessidades dos usuários.
